# План завершения просмотрщика и редактора

Целевой сценарий согласован 26 октября 2026:

1. По умолчанию открывается лёгкий просмотрщик, близкий к текущему интерфейсу.
2. Раса, телосложение, slim-вариант и аксессуары автоматически определяются по скину.
3. Кнопка «Редактировать» открывает расширенный интерфейс того же документа: кисть,
   работа с частями и слоями, история изменений, сохранение PNG.
4. Возврат в просмотрщик показывает текущий результат редактирования.

Разработка продолжается в одном draft PR. `/model-lab` — проверочный вертикальный
срез; до переключения основного viewer необходимо завершить совместимость моделей.
Реализованный объём и ограничения описаны в [руководстве среза](model-lab.md).

## Уже реализовано

- [x] Локальный снимок MLP 1.20.1 и Mson 1.9.3, лицензии, закреплённые версии и хеши.
- [x] Внутренний компилятор используемого поднабора Mson и подготовленные данные моделей.
- [x] Earthpony Steve/Alex и шесть размеров в статической позе.
- [x] Общий RGBA-документ для 2D и 3D, защита служебных пикселей.
- [x] Кисть в один пиксель, ластик, undo/redo, импорт/экспорт квадратного PNG.
- [x] Скрытие отдельных частей и выбор прозрачного слоя для рисования.
- [x] Проверки зеркалирования, UV, размеров, истории и освобождения ресурсов.

## 1. Единый движок моделей и контракт скина

- [ ] Расширить компилятор конструкциями Mson, используемыми оставшимися моделями;
      на неизвестных конструкциях сохранять явную ошибку генерации.
- [ ] Перенести все 12 нечеловеческих рас и их Steve/Alex-варианты; добавить отдельное
      корректное отображение Human вместо принудительного пони-предпросмотра.
- [ ] Реализовать особенности ушей, рогов, морд, грив, ног, плавников и специальных хвостов.
- [ ] Применять шесть размеров автоматически из метаданных, сохранив временные overrides
      редактора отдельно от содержимого PNG.
- [ ] Перенести все формы/длины хвоста, сложенные и раскрытые крылья и необходимую логику поз.
- [ ] Явно моделировать водную/сухопутную форму и дополнительную текстуру морской пони:
      это контекст предпросмотра, который не всегда определяется одним PNG.
- [ ] Нормализовать legacy 64×32 и его HD-варианты с правильным копированием/зеркалированием
      областей. Сохранять сведения об исходном формате и явно обрабатывать ограничения экспорта.
- [ ] Завершить codec: двустороннее чтение/запись служебных пикселей, alpha/default-правила,
      определение slim и совместимость публичного API с существующими потребителями.

## 2. Аксессуары

- [ ] Добавить все восемь ненулевых wearable ID и их текстуры: корона, маффин, witch hat,
      antlers, сумки слева/справа/с обеих сторон и stetson.
- [ ] Перенести крепления, высоты стека и комбинации; задать стабильный порядок предпросмотра.
      Точное повторение игрового порядка конкретного игрока требует UUID-контекста.
- [ ] Учесть различия одиночных/парных сумок, ремень, опускание при раскрытых крыльях,
      legacy-области скина и расовые исключения.
- [ ] Оставить расширяемый выбор источника текстуры аксессуара: стандартный ресурс,
      встроенная область скина или явно загруженная дополнительная текстура.
- [ ] В интерфейсе учитывать лимит PNG: три RGB-канала кодируют до трёх различных ID.
      Не сохранять расширенные комбинации с незаметной потерей информации.

## 3. Основной просмотрщик

- [ ] Подключить общий новый renderer к обычному просмотру и сравнению двух скинов.
- [ ] Вычислять внешний вид из метаданных, без лабораторного принуждения Earthpony.
- [ ] Сохранить компактные загрузку, камеру и сравнение; редактор загружать по требованию.
- [ ] Правильно кадрировать все размеры и аксессуары, сохраняя относительные размеры в сравнении.
- [ ] Сохранить on-demand rendering, корректное обновление кадра при переключениях и
      независимые transforms/текстуры редактируемых документов.
- [ ] Сохранить совместимость встраиваемого standalone viewer; UI и историю редактора
      не включать в его основной bundle.

## 4. Переход viewer → editor → viewer

- [ ] Вынести владение `SkinDocument` из страницы лаборатории в общий контроллер документов
      над маршрутами или эквивалентный реестр. История живёт вместе с документом.
- [ ] Добавить основной маршрут редактора и кнопку «Редактировать» для выбранного скина;
      в сравнении должно быть однозначно понятно, какой документ открывается.
- [ ] Передавать идентификатор уже загруженного документа. Не перезагружать оригинальный
      URL при каждом переходе: это потеряло бы нарисованные пиксели и историю.
- [ ] При возврате показывать тот же изменённый документ; у двух независимо загруженных
      скинов не должно быть общего изменяемого пиксельного буфера.
- [ ] Восстанавливать документ после перезагрузки страницы через локальное сохранение
      и учитывать несохранённые изменения при закрытии/замене документа.
- [ ] Разделить сохраняемые параметры скина и настройки предпросмотра: временные размер,
      поза и видимость частей не должны неявно записываться в экспортируемый PNG.

## 5. Завершение интерфейса редактирования

- [ ] Добавить удобные выбор части/слоя, скрытие ветки, изоляцию, отображение UV и курсора кисти.
- [ ] Добавить масштабирование и панорамирование 2D, пиксельную сетку и подсветку выбранной грани.
- [ ] Завершить кисть: размер, пипетка, корректный перенос через смежные UV-грани,
      предсказуемая работа с прозрачностью и зеркальными/повторяющимися областями.
- [ ] Согласовать инструменты 2D/3D, горячие клавиши и историю: один штрих — одно действие;
      отмена/повтор должны восстанавливать точные RGBA-пиксели.
- [ ] Добавить явное редактирование служебных параметров и проверку их записи при экспорте.
- [ ] Сделать пригодный для мобильного экрана интерфейс, обработку ошибок импорта и понятное сохранение.

Под «слоями» в обязательном объёме понимаются базовая/внешняя геометрия Minecraft-скина
и доступные части модели. Произвольные независимые слои рисования с последующим
сведением — дополнительная возможность, которую не требуется вводить для этого сценария.

## 6. Критерии завершения

- [ ] Проверить геометрию, UV и пропорции по диагностическим текстурам и изображениям
      из запущенного MineLittlePony 1.20.1; текущий срез ещё не подтверждает полный визуальный паритет.
- [ ] Покрыть матрицу 12 рас × 6 размеров × 2 варианта ширины, а также Human,
      legacy/HD, морды, хвосты, крылья и комбинации аксессуаров.
- [ ] Проверить полный сценарий: загрузка → автоматический просмотр → редактирование →
      возврат в просмотр → сохранение/повторный импорт, без потери пикселей и метаданных.
- [ ] Проверить переходы между маршрутами, сравнение, независимость документов и восстановление правок.
- [ ] Проверить отсутствие роста GPU-ресурсов при многократных переключениях и отсутствие
      лишних кадров в покое; измерить производительность на целевых устройствах.
- [ ] Удалить лабораторные обходные решения после переноса возможностей в основной интерфейс
      и завершить обязательные CI-проверки перед переводом PR из draft.

Рекомендуемый порядок следующего прохода: общий resolver и остальные модели → аксессуары →
новый движок в лёгком viewer → переход к редактору без потери документа → завершение инструментов
и сквозная проверка. Это позволит обеим страницам использовать одну и ту же корректную модель.
